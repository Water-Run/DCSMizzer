DCSMIZZER MODEL ROUTER

Status: low-level MIZ toolkit plus an explicit-opt-in isolated DCS runtime
bridge; not a natural-language planner. Only runtime-run can start DCS, only
after its authorization flag. No product command starts Mission Editor.

Typical read path:
  README or README-zh -> this file -> quickstart.md -> exact reference only

Start:
  1. Read quickstart.md.
  2. Run `python Tools/dcsmizzer.py capabilities`.
  3. Run `<command> --help` before relying on an option or output shape.
  4. If the user named a map, terrain-coverage MUST use `--terrain`. If no map
     was named, use its compact default catalog, then query one exact terrain.
  5. Keep discovery bounded: catalog -> exact type/airport -> one
     station/parking/preset. Use the explicit `--details` or `--full` shown by
     current help, and redirect detailed JSON to a work file.
     Keep normal model-visible evidence within a 128 KiB cumulative working
     set; record selected values, not every raw response.
  6. Write full audit/build/verify/inspect JSON to files. Use
     `report-summary PATH` for bounded review; it does not rerun validation.

Hard rules:
  - Never invent or silently substitute an internal type, CLSID, task, country,
    theatre, coordinate, airdrome, parking, station, module, or cloud preset.
  - Evidence and a self-consistent spec do not prove DCS runtime behavior.
  - Use complete_scenario for a user mission. Static reports keep runtime_valid
    null. Only a passing runtime-collect report for the exact MIZ changes that
    artifact's declared runtime tier.
