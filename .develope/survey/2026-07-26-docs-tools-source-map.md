# DCSMizzer Docs/Tools 开发源图（2026-07-26）

## 1. 本文的角色

本页把本轮测绘结果转换为未来 `Docs/` 和 `Tools/` 的输入、顺序与验收门。

它**不是**：

- `Docs/` 的预写副本；
- `Tools/` 的实现计划承诺；
- 对完整产品架构的最终决定；
- 已完成能力清单。

本轮保持 `Docs/`、`Tools/`、根 `AGENTS.md` 不变。只有当相应证据和工具通过本页
定义的门槛，内容才适合从 `.develope/` 提升到产品路径。

## 3. 总体优先级

未来工作应按风险递增，而不是按“看起来最像产品”的顺序：

1. **P0：可追溯读取与验证基座**
   发现文件、哈希、读取 ZIP、安全解析 Lua、保留未知字段、建立引用图。
2. **P1：当前安装数据适配与场景规格**
   验证地图、机场、停机位、类型、任务能力、挂点和用户约束。
3. **P2：最小确定性生成与 DCS 运行验证**
   先覆盖一个受控场景切片，再扩展触发器、资源、多人和战役。
4. **P3：高级动态行为和广泛内容**
   动态生成、MOOSE 类运行时、复杂战役、更多地图/模块。

本轮只完成了 P0/P1 的证据测绘，没有实现任何阶段。

## 4. 未来 `Tools/` 的最小边界

### 4.1 发现与证据清单

职责：

- 接受显式根，而不是硬编码某台机器路径；
- 识别安装、所有 `Saved Games\DCS*`、开发镜像和上游样例；
- 按路径实例和 SHA-256 独立计数；
- 区分活动文件、镜像、回收站和扩展名误命中；
- 记录读取时间、DCS 版本、文件大小、来源类别和访问错误；
- 默认不输出私有任务名、标题或正文。

当前语料验收基线：

- 当前四根应发现 1,049 个 `.miz` 实例；
- 应报告 903 个跨根独立内容；
- 应识别官方镜像 144 个全部为安装子集；
- 应识别上游内部 2 个重复副本；
- `.cmp` 应报告 10 个实例、5 个独立内容；
- Windows 语音 `.cmp` 不得被当作 DCS 战役。

数字是回归夹具的当前机器基线，不应写死为产品常量。

### 4.2 安全 ZIP 层

职责：

- 验证 ZIP 结构、CRC、加密、成员数量和大小；
- 规范化成员路径并拒绝路径穿越；
- 检测重复成员并保留全部 `ZipInfo`；
- 设置总解压大小、单成员大小和压缩比上限；
- 区分核心表、已知资源和未知扩展；
- 读取时不落盘，或只使用受控临时目录；
- 写出时保持确定性成员顺序、时间戳策略和压缩设置。

当前语料验收基线：

- 905 个非镜像 `.miz` 文件实例全成员 CRC 通过；
- 7 个安装任务的 19 个重复资源条目必须被报告；
- 不能把重复成员存在直接判为整个任务无效；
- v6/v16 的核心成员缺失要给出版本化诊断。

### 4.3 Lua 数据解析层

职责：

- 支持实际观测的 Lua 数据子集；
- 支持 UTF-8 BOM、UTF-8 与 CP1251；
- 支持字符串/数字/裸标识符键和稀疏表；
- 保留未知键、Unicode 键和值、历史拼写；
- 拒绝函数执行、I/O、模块加载和开放全局环境；
- 具有深度、节点数、字符串长度和指令/工作量上限；
- 把“语法不支持”“数据模式不符”“文件损坏”分成不同错误。

当前语料验收基线：

- 648 个安装 `mission`、181 个上游 `mission`、76 个 Saved Games
  `mission` 都应安全解析；
- 两个含表内裸标识符键的 Saved Games 样本必须成为回归用例；
- 5 个 CP1251 样本必须保持字符串；
- 5 个 `.cmp` 必须解析其裸键、数字阶段和 Unicode locale 键；
- 解析器不得执行 `initScript`、触发器脚本或存档 `.lua` 资源。

### 4.4 原始任务模型

职责：

- 反映存档、Lua 表和资源引用的原始结构；
- 每个节点保留来源成员、原始键、格式版本和诊断；
- 未知字段以 opaque/extension 形式往返；
- 区分字段缺失、空表、显式 `false` 和 `nil`；
- 保留重复资源、大小写和 locale；
- 提供跨 ID/字典/资源引用图。

当前语料验收基线：

- 保留 `uncontrolled` 与 `uncontrollable`；
- 保留 `lenght`、`lenghtRope`；
- 保留 `dynSpawnTemplate`、`DTC`、`dataCartridge`、`datalinks`、
  `coldAtStart` 等扩展；
- 保留多语言组 `task` 和 `.cmp` 的字形易混淆 Unicode 键；
- 不因 v6 缺字典而合成“原文件已有”的假数据。

### 4.5 规范化语义模型

职责：

- 为 Agent 提供地图、联盟、国家、组、单位、槽位、航路、任务、目标、资源与战役；
- 原始值和规范值双轨保存；
- 每次别名、翻译、默认值和版本迁移都有规则 ID 与来源；
- 允许“未知”，而不是强迫选择最近枚举；
- 区分数据事实、用户约束、生成决定和验证结果。

建议的核心记录：

| 记录 | 必须携带 |
|---|---|
| `SourceVersion` | DCS 版本、上游远端/分支/提交、提取时间 |
| `EvidenceRef` | 来源根、成员类型、哈希或数据集 ID |
| `RawValue` | 未规范化值 |
| `NormalizedValue` | 规范值或未知 |
| `RuleRef` | 别名/迁移/翻译规则 |
| `Confidence` | 已验证、候选、冲突、未知 |

### 4.6 本机 DCS 数据适配

职责：

- 从当前安装或经过验证的导出读取类型、国家、任务能力和武器；
- 获取地图投影、机场、跑道、停机位和高度；
- 建立机型—挂点—CLSID 兼容关系；
- 记录模块和地图版本；
- 与 pydcs、BriefingRoom、Retribution、GTD 快照交叉比较；
- 冲突时保留各版本，不静默合并。

进入生成前的最低验收：

- 对目标机型的精确 `type` 和模块要求有本机证据；
- 对每个挂载有挂点兼容与武器 CLSID 证据；
- 对起飞机场/停机位有地图版本和占用检查；
- 对任务能力有 DCS 支持证据；
- 对用户时代约束有单位/武器可用性检查。

### 4.7 场景规格与规划

自然语言应先转换为可审计的场景规格，而不是直接写 Lua。至少包含：

- 地图、时代/日期、联盟、国家和敌我关系；
- 玩家数、机型、启动状态、机场与备降；
- 目标、任务类型、威胁、友军和支援；
- 载荷、油量、无线电、天气、时长；
- 成功、失败、退出和战役推进条件；
- 随机种子、数据版本和允许/禁止替代项。

缺失信息可使用明确默认值；与用户要求冲突的限制必须报告并请求决定。不能静默替换
地图、机型、武器、目标或任务类型。

### 4.8 序列化器

序列化器应在读取与数据适配稳定后开始。最低目标不是“覆盖全部 DCS”，而是：

- 一个当前格式、单地图、单机型、单玩家的最小场景切片；
- 确定性 ID、成员顺序、种子和版本记录；
- 完整生成 `mission`、`options`、`warehouses`、字典和资源映射；
- 只加入场景需要的资源；
- 输出与安装/上游/参考任务隔离；
- 生成后重新读取，不依赖内存对象自证正确。

禁止从官方任务复制模板、简报、媒体或脚本作为“捷径”。

### 4.9 静态验证器

建议分层报告：

1. **Archive**：ZIP、CRC、路径、大小、重复成员；
2. **Syntax**：编码与 Lua 数据语法；
3. **Schema**：版本化必需字段与类型；
4. **References**：ID、字典、资源、机场、停机位、组/单位链接；
5. **DCS data**：类型、任务、挂点、CLSIDs、地图与模块；
6. **Scenario**：用户约束是否保留；
7. **Campaign**：阶段、区间、引用与结果闭包；
8. **Runtime pending**：必须在 DCS 才能验证的项。

“通过静态验证”不得缩写成“任务可玩”。

### 4.10 DCS 运行验证

只有在可用、受用户授权的 DCS 环境中，才增加：

- 加载任务；
- 读取 DCS 日志和 Lua 错误；
- 检查玩家槽位与起飞位置；
- 检查 AI 出生、航路、触发器和目标；
- 检查成功/失败与战役推进；
- 必要时执行最小人工/自动 smoke test。

运行验证必须记录 DCS 版本、模块、地图、设置和实际运行结果。本轮未运行。

## 5. 未来 `Docs/` 的建议来源结构

以下只是主题与证据门，不要求照搬目录名。

### 5.1 项目与证据说明

内容：

- DCSMizzer 是什么、当前能做什么；
- 证据优先级；
- 版本、许可、版权和隐私；
- “目录/计划不等于实现”的状态约定。

提升条件：

- 实际工具入口已经存在；
- 示例命令运行通过；
- 能力表与仓库文件一致。

### 5.2 MIZ/CMP 格式指南

来源：

- 本轮存档、编码、版本和 CMP 统计；
- 最小编辑器重存实验；
- 解析器回归测试。

提升条件：

- 能解释版本化核心成员；
- 覆盖重复成员、CP1251、裸键和未知字段；
- 文档示例是自制最小数据，不复制官方任务。

### 5.3 任务数据模型

来源：

- 联盟—国家—类别—组—单位—路线—任务数据图；
- 触发器、目标、资源、仓库和战役引用；
- 本机类型/挂点/地图数据适配。

提升条件：

- 模型与工具代码一一对应；
- 未知字段与 provenance 有明确表示；
- 至少用当前语料自动核验。

### 5.4 场景创作指南

内容：

- 如何表达时代、联盟、任务、玩家、天气和启动状态；
- 默认值、限制和替代决策；
- 目标、节奏、支援、成功/失败；
- 单任务与战役的差异。

提升条件：

- 对应场景规格和生成器确实存在；
- 每个公开示例都生成、回读并完成相应验证；
- 不承诺未运行的地图、模块或任务类型。

### 5.5 数据与兼容矩阵

内容：

- DCS 版本；
- 地图、模块、机型、机场、武器和任务能力；
- 来源与最后验证时间；
- 当前支持、实验、未覆盖状态。

提升条件：

- 数据来自可重现导出或当前安装；
- 冲突和快照版本可见；
- 不把市场可售模块等同于本机已验证能力。

### 5.6 验证与故障诊断

内容：

- Archive/Syntax/Schema/References/DCS data/Scenario/Runtime 分层；
- 常见解析器限制与旧格式；
- 如何报告未验证项；
- 安全与版权规则。

提升条件：

- 每个诊断都有实际工具输出与回归夹具；
- 文档不把警告、跳过或回退写成通过。

## 6. 测绘驱动的回归夹具矩阵

未来测试不需要提交受版权任务本体。可以：

- 用自制、最小 Lua/ZIP 片段复制**结构特征**；
- 对本机合法语料运行不提交文件的集成测试；
- 记录聚合预期，不记录私有标题和正文。

建议夹具：

| 结构特征 | 来源证据 | 自制测试目标 |
|---|---|---|
| v6 缺字典/资源映射 | 1 个安装任务 | 版本化缺失诊断 |
| v16 缺 `options` | 7 个安装任务 | 旧格式警告 |
| 重复 ZIP 资源 | 7 个安装任务 | 多条目报告与稳定选择 |
| CP1251 `mission` | 5 个 Saved 样本 | 编码检测与往返 |
| 表内裸标识符键 | 2 个 Saved 样本 | 安全 Lua 子集 |
| 本地化组 `task` | 安装/上游 | raw + normalized 双轨 |
| `dynSpawnTemplate`/DTC | 当前安装 | 未知/现代字段保留 |
| Unicode confusable CMP 键 | 当前 `.cmp` | 精确键保留 |
| 每阶段四任务与分数区间 | 1 个 `.cmp` | 区间/引用验证 |
| 相对 CMP 任务引用 | 144 个引用 | 可移植路径解析 |

## 7. 进入生成开发前的 P0 完成门

必须同时满足：

- 当前 903 个独立语料都可清单化，不泄露正文；
- 905 个非镜像文件实例的 ZIP 诊断可重现；
- 648 + 76 + 181 个 `mission` 都由项目自己的安全解析层读取；
- 5 个 `.cmp` 和 144 个引用被解析、解析路径和区间；
- 原始模型保留未知字段、Unicode、历史拼写和重复资源；
- 版本/来源信息进入每份报告；
- 解析器不会执行存档脚本；
- 回归测试使用自制结构夹具或本机只读集成测试；
- 文档只声称实际存在的入口和检查。

完成 P0 仍不等于生成能力完成。

## 8. 进入首个生成切片的 P1 完成门

对选定的一个地图、一个机型和一个任务类型，必须同时具备：

- 当前安装的地图、机场、跑道、停机位证据；
- 当前安装的机型、国家、任务能力和模块证据；
- 每个挂点/CLSID 的兼容证据；
- 一个明确、版本化的场景规格；
- 自制最小资源与简报；
- 静态验证器能证明用户约束未丢失；
- 输出不写入 DCS 安装、上游或参考任务目录；
- 有计划的 DCS 加载验证。

这比一开始覆盖全部地图、全部飞机、战役和动态脚本更符合当前证据成熟度。

## 9. 根治理文件的后续改进建议

本轮不修改根 `AGENTS.md`。从测绘中得到的候选改进是：

1. 明确 `.develope/survey/` 是调查结论，`.develope/reference/` 是版本化提取，
   `Docs/` 是已实现能力的产品说明；
2. 要求每次调查报告实例数、唯一哈希数和镜像关系；
3. 把 Archive-valid、Parse-valid、Static-valid、Runtime-valid 四种状态分开；
4. 要求默认不记录 Saved Games 私有文件名、标题、简报和哈希清单；
5. 规定 Lua 数据解析不得执行任务脚本；
6. 要求 `.cmp` 引用、区间和 `.miz` 结果形成跨文件验证；
7. 对参考快照增加上游提交/DCS 版本/生成命令/覆盖范围元数据；
8. 在声称完成前列出无法运行的 DCS 验证。

这些建议应在对应工具和流程确定后再修改治理文件，避免把尚未实现的工作流写成
强制但不可执行的规则。

## 10. 明确延后

以下工作不属于本轮，也不应从本文误读为已获授权或已完成：

- 创建 `Tools/` 代码框架；
- 写 `Docs/` 产品手册；
- 修改根 `AGENTS.md`、README 或提示词；
- 自动恢复/复制/重写本机任务；
- 从官方任务提取并分发资源或叙事；
- 执行 MOOSE 或其他任务脚本；
- 一次性支持全部地图、模块、武器和战役；
- 推断当前市场、模块状态或未安装内容。

## 11. 推荐的下一次开发切片

在用户明确要求进入代码开发后，推荐只做 P0 的第一个闭环：

```text
显式根发现
  → SHA-256/ZIP 清单
  → 安全读取核心 Lua 表
  → 原始字段与引用报告
  → 自制夹具测试
  → 对当前本机语料只读回归
```

该切片不生成任务，却能把本轮一次性调查转换成可重复测绘基础。只有这个闭环通过后，
再确定最小生成场景。
