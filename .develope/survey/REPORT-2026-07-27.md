## Tools/Docs admission rules

Model-facing construction may now begin, subject to these non-negotiable rules:

1. expose evidence version and authority with every exact-data lookup;
2. never label a legacy or upstream value as current local DCS truth;
3. distinguish archive, parse, static, and runtime validation in APIs and prose;
4. present pydcs/BriefingRoom registry, pylon, and parking results only as
   provenance-qualified snapshot evidence when no version-matched runtime
   export exists; never upgrade a fallback to current runtime truth;
5. use `terrain-coverage` rather than restricting a request to locally
   installed maps, while applying the strict provenance classification,
   retaining any non-commit-bound audit warning, evaluating the full identity
   graph, preserving all source conflicts, and keeping `runtime_valid: null`;
6. keep generated outputs separate from installed DCS, Saved Games evidence,
   official mirrors, and upstream clones;
7. resolve parking per airport and slot, primary then secondary without field
   mixing, and apply pydcs `slot_version` semantics exactly;
8. hard-reject coordinates from an upstream rectangle only when that source is
   self-consistent, and inventory route/unit, bullseye, trigger-zone, and
   supported task coordinates;
9. accept only the seven exact first-waypoint start pairs; linked runway or
   parking facilities must be same-coalition static/ship units, and an
   `Escort` source cannot target itself;
10. count only plane/helicopter `Player` or `Client` units as human slots,
    preserve sparse global goal keys, and require a supported writer for every
    finite-vocabulary flag read without claiming temporal reachability;
11. reject live or dangling final-output symlinks, bind validation to the open
    same-directory candidate, and use an atomic final path update while
    explicitly requiring a trusted output directory rather than claiming
    end-to-end atomicity.
