# DCSMizzer 完整测绘闭环实施计划

**日期：** 2026-07-27
**范围：** 只修改 `.develope/` 内的开发调查程序、测试、匿名机器基线和调查文档。
`Tools/` 与 `Docs/` 在本计划所有完成门通过前保持未构造状态。

## 1. 目标

把当前一次性、以 Markdown 为主的调查转换为可重复、可更新、可追溯的开发测绘
闭环。闭环必须能从显式证据根重新得到 MIZ/CMP 语料结论，安全读取实际 Lua 数据，
核对六个上游与参考快照，并说明当前 DCS 安装数据能与不能证明什么。

本计划不实现：

- 面向 Agent 的产品 `Tools/` API 或 CLI；
- 产品 `Docs/`；
- 任务、战役或脚本生成；
- 将官方、Saved Games 或上游任务正文、文件名、哈希清单提交进仓库；
- 无用户授权的 DCS 安装或任务写入。

## 2. 开发目录与职责

```text
.develope/survey/
├─ dcsmizzer_survey/
│  ├─ model.py          # 来源、诊断、存档、Lua 和语料结果模型
│  ├─ discover.py       # 显式根扫描、扩展名识别、访问错误
│  ├─ archive.py        # SHA-256、ZIP/CRC/路径/大小/重复成员检查
│  ├─ lua.py            # 只解析数据的 Lua 子集，不执行代码
│  ├─ mission.py        # MIZ 核心表、编码和匿名语义聚合
│  ├─ campaign.py       # CMP 结构、区间和相对 MIZ 引用
│  ├─ upstream.py       # Git 远端、分支、提交、许可与快照版本
│  ├─ dcs.py            # 本机 DCS 版本及可验证数据源测绘
│  ├─ report.py         # 匿名 JSON 基线与 Markdown 输入数据
│  └─ cli.py            # 开发测绘入口
├─ tests/
│  ├─ fixtures/         # 自制最小 Lua/MIZ/CMP 结构，不含第三方内容
│  └─ test_*.py
├─ baselines/           # 可提交的匿名聚合基线
└─ run_survey.py        # 从仓库根可直接运行的薄入口
```

采用 Python 标准库和 `unittest`。开发测绘入口不进入产品 `Tools/`，不承诺未来产品
API 与其相同。

## 3. 核心接口和数据流

证据根由调用者显式提供：

```text
EvidenceRoot(name, kind, path, version?)
```

`name` 是报告中的公开标签；绝对 `path` 只在进程内使用。默认输出不包含绝对路径、
相对任务文件名、任务标题、正文或逐文件 SHA-256。

数据流：

```text
EvidenceRoot
  → FileInstance
  → ContentDigest + ArchiveInspection
  → ParsedLuaTable
  → MizObservation | CampaignObservation
  → CorpusAggregate
  → anonymous baseline JSON
```

所有诊断至少包含：

- 稳定代码；
- 层级（archive、syntax、schema、reference、DCS-data、runtime）；
- 严重度；
- 来源标签；
- 是否影响本次统计；
- 不泄露文件名的匿名实例序号。

## 4. 安全边界

### 4.1 ZIP

- 不提取到工作区；
- 拒绝绝对路径、盘符、UNC 和 `..` 穿越；
- 检查成员数、单成员大小、总解压大小和压缩比；
- 检测加密、重复成员和 CRC；
- 重复资源是歧义诊断，不自动等同于存档损坏；
- 保留所有 `ZipInfo` 供分析，不用名称集合抹掉重复项。

### 4.2 Lua

解析器只接受实际观测的数据子集：

- 全局/局部变量赋值；
- 表、字符串、数值、布尔、`nil`；
- 数字键、字符串键、裸标识符键和隐式数组键；
- 注释、Unicode、常见 Lua 转义、UTF-8 BOM、UTF-8 和 CP1251；
- 受限的 `_("<text>")` 数据包装写法。

解析器不支持或不执行：

- 函数定义或调用；
- `require`、模块加载、I/O、系统库；
- 运算表达式、元表或任意全局访问；
- MIZ 中的 `Scripts/`、触发器脚本文本和 `initScript*`。

深度、节点、字符串、输入大小和工作量均有限额。模式不支持、限额命中和数据损坏是
不同诊断。

## 5. 测试策略

核心逻辑执行 RED-GREEN-REFACTOR：

1. 自制 ZIP 覆盖正常核心成员、重复成员、路径穿越、损坏 CRC、大小和压缩比限制；
2. 自制 Lua 覆盖裸键、数字键、稀疏表、Unicode 易混淆键、CP1251、转义和恶意
   函数调用拒绝；
3. 自制 CMP 覆盖单任务阶段、四任务分数区间、缺失引用、重叠/空洞区间；
4. 临时证据根覆盖实例数、根内唯一、跨根去重、镜像关系、访问错误和隐私输出；
5. 本机只读集成测试覆盖安装、Saved Games、官方镜像和六个上游。

测试断言使用手工确定的最小结构，不从实现代码计算期望值。

## 6. 阶段完成门

### Gate A：语料与存档

- 当前显式四根的实例数、唯一内容、镜像和跨根重合可由一条命令重现；
- 全部非镜像 MIZ 的 ZIP/CRC 结果可重现；
- 旧版本缺成员、重复成员和坏存档有稳定诊断；
- 输出默认不泄露私有路径、文件名、标题、正文或哈希清单。

### Gate B：Lua、MIZ 与 CMP

- 项目自己的安全解析器读取当前全部 `mission`；
- 核心表解析结果和编码覆盖可重现；
- 5 个独立 CMP、阶段、区间和相对引用可重现；
- 未知字段、历史拼写和 Unicode 键不会因规范化而消失；
- 任何脚本内容均未执行。

### Gate C：上游与参考快照

- 六个上游的远端、分支、提交、工作树和许可证据可重现；
- 每个参考数据集都有来源项目、来源文件、提交、提取器版本、生成时间和覆盖范围；
- 当前快照与当前上游一致，或明确标记为冻结旧版本且不会被当作当前事实；
- 检查不再只抽样 pydcs。

### Gate D：当前 DCS 精确数据

- 记录本机 DCS、Steam build、已安装地图/模块与数据来源；
- 对类型、国家、任务能力、挂点/CLSID、机场/跑道/停机位分别给出：
  已验证来源、覆盖范围、冲突和无法验证项；
- 参考上游不能冒充当前本机权威数据；
- 编辑器或 DCS 运行时才能证明的事项独立列出。

### Gate E：运行时与完成声明

- 可安全执行的编辑器重存或 DCS 加载检查已运行并记录版本与结果；
- 无法自动化或需要人工操作的检查有明确步骤、输入和阻塞原因；
- Archive-valid、Parse-valid、Static-valid、Runtime-valid 不混写；
- 所有调查文档由当前匿名机器基线支持，过时数字已更新或保持明确冻结标签。

只有 Gate A–E 都完成，或 Gate E 的外部阻塞经过实际验证并被用户接受，才能把
`.develope` 测绘称为“彻底完成”。

## 7. 风险

- 当前语料约 4 GB，完整 CRC 和语义聚合需要流式处理，不能把所有存档同时载入内存；
- Lua 解析器若追求完整 Lua 会扩大攻击面，必须保持数据子集；
- DCS 数据部分可能依赖编辑器运行环境或专用导出，静态安装文件不足时不能猜测；
- 上游 `dev`/`master-ng` 会持续变化，基线必须绑定提交；
- 官方与 Saved Games 内容只能在本机只读使用，测试夹具必须自制。
